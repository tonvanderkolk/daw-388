# 0.37.0 MIDI Learn Implementation Plan

> **For agentic workers:** REQUIRED: Use superpowers:subagent-driven-development (if subagents available) or superpowers:executing-plans to implement this plan. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Any MIDI controller that sends CC or notes can move the faders, PAN, MUTE and SOLO of each track, the STEREO MASTER and PLAY, STOP, REC and RTZ, after a right-click, MIDI Learn. There is pickup against jumps, and feedback so motor faders and lamps follow the screen.

**Architecture:**
- The platform delivers raw MIDI messages and sends bytes back. `app-desktop` does this with `midir`; the test platform takes injected messages.
- A new module `crates/ui/src/midi.rs` holds everything else:
  - the binding table (saved in `Preferences`);
  - learning, translation and pickup;
  - the per-frame feedback.
- Values are applied the way the mouse applies them: set the field, send it to the engine and `mark_dirty`. So LINK, undo-free mixer changes and the engine stay as they are.

**Tech Stack:** Rust 2024, egui/eframe 0.37, midir 0.11.

**Spec:** `docs/superpowers/specs/2026-11-05-midi-learn-design.md`.

**Conventions:**
- Toolchain: `export PATH="$(brew --prefix rustup)/bin:$PATH"` before any cargo command.
- UI text and code comments in English. CHANGELOG, ROADMAP and PROJECT.md are in Dutch, with no em or en dashes and no comma before en, of or noch.
- **Do not commit.** Ton tests himself and says "commit en push".
- Checks: `cargo fmt --all --check`, `cargo clippy --workspace --all-targets -- -D warnings`, `cargo test --workspace`.

**Choices where this plan fills in the spec (tell Ton):**
1. **Hot-plugging:** the port rescan runs from the UI's frame loop, at most every 2 seconds. A controller plugged in while the app sits idle shows up at the next repaint. Incoming MIDI always wakes the UI.
2. **Learning:** learning takes CC and note-on messages only. Clock, active sensing, program change and pitch bend are ignored, so a running clock cannot "learn" itself.
3. **Feedback for transport keys:** the transport keys get no feedback (there is no state that fits).

/// What can be bound.
#[derive(Debug, Clone, Copy, PartialEq, Eq, Hash, Serialize, Deserialize)]
#[serde(tag = "kind", content = "track", rename_all = "snake_case")]
pub enum Control { Fader(usize), Pan(usize), Mute(usize), Solo(usize), Master, Play, Stop, Rec, Rtz }

/// Where a message comes from.
#[derive(Debug, Clone, PartialEq, Eq, Hash, Serialize, Deserialize)]
pub struct Source { pub port: String, pub channel: u8, pub kind: SourceKind, pub number: u8 }

#[derive(Debug, Clone, Copy, PartialEq, Eq, Hash, Serialize, Deserialize)]
#[serde(rename_all = "snake_case")]
pub enum SourceKind { Cc, Note }

#[derive(Debug, Clone, PartialEq, Serialize, Deserialize)]
pub struct Binding { pub control: Control, pub source: Source }

/// A message as the platform hands it over.
pub struct MidiMessage { pub port: String, pub bytes: Vec<u8> }

/// A CC or note-on/off with its value (velocity 0 for note-off), or `None` for anything else.
pub fn parse(message: &MidiMessage) -> Option<(Source, u8)>

### Task 2: value conversion and pickup

**File:** `crates/ui/src/midi.rs`.

```rust
/// A continuous control's value on the 0 to 127 scale of a CC.
pub fn to_cc(control: Control, value: f32) -> f32  // fader/master: fader_position(db) * 127; pan: pan * 63.5 + 63.5
pub fn from_cc(control: Control, cc: u8) -> f32    // the inverse; pan 64 is exactly 0.0, 0 is -1.0, 127 is +1.0

/// Pickup per binding: wait until the controller reaches the screen value.
#[derive(Default)]
pub struct Pickup { picked: bool, last: Option<u8> }
impl Pickup {
    /// Whether `incoming` may move a control now at `screen` (both on the CC scale).
    pub fn admit(&mut self, incoming: u8, screen: f32) -> bool  // picked, or within 2, or crossed since `last`
    pub fn drop(&mut self)                                       // the screen moved on its own
}
```

- [ ] **Step 1: Failing tests:**
  - `from_cc(Fader, 0)` is `MIN_DB` (or the bottom of the taper), 127 is +6 dB, and `to_cc(Fader, 0.0)` round-trips within one step;
  - pan 0, 64 and 127 give -1, 0 and +1;
  - pickup: far away, nothing; within 2, admitted; crossing from below to above, admitted; once picked, everything is admitted until `drop`.

### Task 3: the binding table and learning

**File:** `crates/ui/src/midi.rs`.

```rust
#[derive(Default)]
pub struct Midi {
    pub bindings: Vec<Binding>,
    pub learning: Option<Control>,
    pickups: HashMap<Control, Pickup>,
    /// What feedback last sent per control (CC scale); `None` before the first frame.
    sent: HashMap<Control, u8>,
}
impl Midi {
    /// While learning: the first CC or note-on becomes the binding for `learning`; the same source
    /// bound elsewhere moves here. Returns the control that was learnt.
    pub fn learn(&mut self, source: &Source, value: u8) -> Option<Control>
    pub fn forget(&mut self, control: Control)
    pub fn bound(&self, control: Control) -> Option<&Binding>
    pub fn control_of(&self, source: &Source) -> Option<Control>
}
```

- A note-off or a note-on with velocity 0 does not learn (a key's release would otherwise bind).

### Task 5: applying messages, LINK and the transport

**File:** `crates/ui/src/midi.rs` (`impl DawApp`) and the frame loop in `lib.rs` (call `self.poll_midi()` before the views).

```rust
pub(crate) fn poll_midi(&mut self) {
    for message in self.platform.midi_poll() {
        let Some((source, value)) = midi::parse(&message) else { continue };
        if Esc pressed... (handled in handle_keys: Esc clears self.midi.learning)
        if let Some(control) = self.midi.learn(&source, value) { status "MIDI: {label} ← {describe}"; store_preferences; continue }
        let Some(control) = self.midi.control_of(&source) else { continue };
        self.apply_midi(control, source.kind, value);
    }
}
```

- `apply_midi` does the following:
  - **Fader(i):** pickup against `to_cc(Fader, tracks[i].fader_db)`, then set `fader_db = from_cc(..)`, `send_channel(i)` and `mark_dirty`, and set `sent[control] = value`, so feedback does not echo.
  - **Pan(i):** the same with `pan`.
  - **Master:** the same with `master_db` and `Command::SetMaster`.
  - **Mute(i) and Solo(i):** on a press (value > 63, or a note-on above 0), toggle exactly as the strip keys do (SOLO sends `SetSolo` and sets `link_touched = Some(i)`).
  - **Play, Stop, Rec and Rtz:** on a press, call `play()`, `stop()`, `record()` and `rtz()`.
- LINK: `sync_links` runs after the views and picks up the change on one side, as it does for the mouse. Nothing extra is needed.
- Esc in `handle_keys` cancels learning (with status "MIDI Learn cancelled").

### Task 6: feedback

**File:** `crates/ui/src/midi.rs` (`DawApp::midi_feedback`, called once a frame after `sync_links`).

- For each binding of a continuous control or MUTE/SOLO:
  - compute its CC value (MUTE and SOLO are 127 or 0);
  - if it differs from `sent`, send `B0+ch number value` (or `90+ch` for a note source) to `source.port`, store it, and call `pickups[control].drop()` unless the value came from MIDI this frame.
- On the first frame and after `open_project`/`reset`, clear `sent`, so everything is sent once and motor faders go to the project's state.

```rust
pub struct MidiHub {
    inputs: HashMap<String, midir::MidiInputConnection<()>>,
    outputs: HashMap<String, midir::MidiOutputConnection>,
    tx: Sender<MidiMessage>, rx: Receiver<MidiMessage>,
    ctx: egui::Context,
    last_scan: Option<Instant>,
}
impl MidiHub {
    /// Every 2 s at most: connect to new ports and drop the ones that went away.
    fn rescan(&mut self)
    pub fn poll(&mut self) -> Vec<MidiMessage>   // rescan, then drain rx
    pub fn inputs(&self) -> Vec<String>
    pub fn send(&mut self, port: &str, bytes: &[u8])
}
```

- Each input connects with its own `MidiInput::new("DAW 388")`, because `connect` consumes it. Its callback sends `MidiMessage { port, bytes }` and calls `ctx.request_repaint()`.
- Errors are logged once per port, not every scan.
