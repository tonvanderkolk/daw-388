# 0.36.0 Mixdown Deck Implementation Plan

> **For agentic workers:** REQUIRED: Use superpowers:subagent-driven-development (if subagents available) or superpowers:executing-plans to implement this plan. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A second, two-track machine that records the STEREO MASTER live (with every fader ride and effect move) through a 1/4" deck, a cassette or straight to digital, keeps the takes as "Mix 1", "Mix 2" and so on in the project, plays them back and saves them as files. The same machines are offered in the export.

**Architecture:**
- `tape` gets a `MixdownDeck`: two channels, three fixed machine profiles, built from the 388's own blocks (saturation, filters, wow and flutter, hiss).
- The engine runs the deck after the STEREO MASTER and MONO. While MIX REC is on you hear the deck on LISTEN STEREO, and while the transport plays the engine streams the deck's frames, plus the clean ones when asked, through a ring of its own. It can also play one mix back on the main output.
- The UI writes that stream into temporary files (`recording.rs`), adopts finished mixes into `<project>/mixes/` and keeps the list in `project.json`. The deck itself is a new module `crates/ui/src/deck.rs`: the panel under the transport, or a window in the compact console.

**Tech Stack:** Rust 2024, egui/eframe 0.37, rtrb, hound.

**Spec:** `docs/superpowers/specs/2026-11-05-mixdown-deck-design.md`.

**Conventions:**
- Toolchain: `export PATH="$(brew --prefix rustup)/bin:$PATH"` before any cargo command.
- UI text and code comments in English. CHANGELOG, ROADMAP and PROJECT.md are in Dutch, with no em or en dashes and no comma before en, of or noch.
- **Do not commit.** Ton tests the build himself and says "commit en push". Each task ends with the checks, not a commit.
- Checks: `cargo fmt --all --check`, `cargo clippy --workspace --all-targets -- -D warnings`, `cargo test --workspace`.
- Nothing in the audio thread allocates: buffers are made in `new`, and `Arc`s go back through the garbage ring.

**Choices where this plan fills in the spec (tell Ton):**
1. **MIX REC needs a saved project,** just like REC does ("Save the project first: the mix goes into the project folder").
2. **What counts as a take:** the deck only records in `State::Playing`, so a count-in, a search or winding is not recorded. A REPEAT jump stays within the same take, because it is one stretch of audio from the output. STOP, REW, F FWD, RTZ and STC end the take.
3. **Very short takes:** a take shorter than half a second (an accidental PLAY and STOP) is thrown away, with a status line that says so.
4. **Recording and mixing at once:** you can record tracks while the deck records. The deck takes what you hear on STEREO, so the input of an armed track comes along only if it reaches the stereo mix.
5. **Playing a mix and the transport:** playing a mix stops the 388 transport. PLAY, REC and the winding keys stop the mix again.
6. **Print through...:** this runs offline, like an export, with a progress bar in the deck. It gives a new mix with its own clean copy, so it can be printed again.
7. **The cassette's noise reduction:** it is fixed, a Dolby B-like treatment of the hiss above about 4 kHz (-10 dB). There is no switch.

```rust
/// What the audio thread hands the writer for the mixdown deck.
#[derive(Debug, Clone, Copy, PartialEq)]
pub enum MixItem {
    /// A mix starts; `clean` says whether frames carry a clean copy.
    Start { clean: bool },
    /// One frame: the deck's left and right, then the clean left and right (zero when not kept).
    Frame([f32; 4]),
    Stop,
}
```

- In `recorder()`: make one more ring with room for two seconds of frames. Add `Recorder::drain_mix(&mut self, each: impl FnMut(MixItem))` and include the mix ring in `is_abandoned`.
- Add `Command::SetDeck { machine: Machine, rec: bool, clean: bool }`. The engine keeps `deck: MixdownDeck` (made in `create`), `deck_rec`, `deck_clean` and `deck_taking: bool`.
- In `render`, right after `master_peaks` and the energy (around `crates/engine/src/lib.rs:1154`), with `left` and `right` being the master after MONO:

```rust
let (clean_l, clean_r) = (left, right);
let taking = self.deck_rec && self.state == State::Playing;
if self.deck_rec {
    (left, right) = self.deck.process(left, right);
}
if taking != self.deck_taking {
    let item = if taking { MixItem::Start { clean: self.deck_clean } } else { MixItem::Stop };
    let _ = self.rec_out.mix.push(item);
    self.deck_taking = taking;
}
if taking {
    let clean = if self.deck_clean { [clean_l, clean_r] } else { [0.0; 2] };
    let _ = self.rec_out.mix.push(MixItem::Frame([left, right, clean[0], clean[1]]));
}
```

  Because `left` and `right` now feed `Listen::Stereo`, you hear the deck while MIX REC is on. The click is added later, so it never reaches the mix. A `SetDeck` with `rec: false` during a take pushes `Stop` on the next frame.

### Task 3: playing a mix back

**Files:** Modify `crates/engine/src/lib.rs`.

- Add `Command::PlayMix(Option<[Arc<TrackAudio>; 2]>)`. `Some` stops the transport (as `Stop` does) and plays the pair from its start. `None` stops it. The old pair goes into the garbage ring, both `Arc`s.
- `Play`, `Record`, `Rewind`, `FastForward`, `ReturnToZero` and `SearchToCue` stop a playing mix first.
- In `render`, while a mix plays: the main output is `mix[i] * self.phones` on L and R (LISTEN does not apply), the master meters and peaks take the mix, and the console is not heard. At the end the mix stops by itself.
- Publish in `Shared`: `mix_position` (samples, `AtomicU64`, `NO_CUE` when not playing). Add `EngineHandle::mix_position_seconds() -> Option<f64>`.

### Task 7: playing, saving and printing a mix

**Files:** Modify `crates/ui/src/deck.rs`, `crates/ui/src/export.rs` and `crates/ui/src/lib.rs`.

- **Playing:** `play_mix(i)` loads the WAV the first time with `daw388_project::load_audio` (resampled to the engine rate as a track is), then sends `PlayMix(Some(pair))` and sets `playing_mix`. `stop_mix()` does the reverse. Each frame, clear `playing_mix` once `mix_position_seconds()` is `None`.
- **Saving:** `save_mix(i)` uses the folder, format and bit depth of the Export window, with the name `<base>_<mix name>`. It writes with `write_audio` and sets the peak note with `export_peak_note`. Keep it on the UI thread: one stereo file is fast enough. If it turns out to block noticeably on long mixes, move it to `platform.spawn` like the export.
- **Printing:** `print_mix(i, machine)` runs on `platform.spawn` and reads the clean copy. It runs `MixdownDeck` offline in blocks and writes a new deck file and a copy of the clean file into `mixes/`. The result arrives like an export, through a channel, and becomes a new `Mix` (one undo step). It shows a progress bar in the deck.
- **The export's Through:** `ExportChoices.through: Machine` (default `Direct`, saved with the other export choices). In `export::run`, the stereo render `[l, r]` goes through a fresh `MixdownDeck` before `place`. Stems never do.
